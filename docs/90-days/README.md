# 91 天前端学习计划

这是一条面向零前端经验学习者的完整执行路线。课程以 IssueFlow 为持续案例，
共 **13 周、91 天、至少 182 小时**。每天不是简单“看一章”，而是完成一组可验证的
学习活动：回忆、精读、源码追踪、动手实验、独立修改和学习记录。

::: tip 课程承诺
只要按每天 120 分钟执行并保留证据，三个月后你应该能够独立理解、修改、测试和解释
一个现代 TypeScript + React 项目，而不只是照抄组件。
:::

## 适合谁

- 完全没有 HTML、CSS、JavaScript 或 React 经验；
- 有 C#/.NET、Java 或其他后端经验，但缺少浏览器和 TypeScript 心智模型；
- 学过零散前端语法，却无法独立完成真实功能；
- 希望用一个持续演进的产品，而不是互不相干的小示例学习。

## 每天固定的 120 分钟

| 时间         | 活动                               | 必须留下的证据            |
| ------------ | ---------------------------------- | ------------------------- |
| 0–15 分钟    | 不看答案回忆昨天，并写下今天的预测 | 3～5 条预测或问题         |
| 15–40 分钟   | 阅读当天概念和关联章节             | 自己写的概念图或对比表    |
| 40–80 分钟   | 跟随步骤观察真实源码或完成实验     | 命令输出、截图或测试结果  |
| 80–110 分钟  | 关闭步骤说明，独立完成变体任务     | Git diff 与验收结果       |
| 110–120 分钟 | 复盘、提交和安排补救               | 日志、commit 或明确的卡点 |

阅读不算完成。当天必须产生可以被别人检查的结果。

## 完成规则

每天达到以下五项才算完成：

1. 运行当天涉及的代码或页面；
2. 写下至少一个先预测、后验证的结果；
3. 完成独立变体，而不是只跟做；
4. 执行与改动匹配的最小测试；
5. 用自己的话回答当天验收问题。

一周内有两天未完成，应先使用周末的补救时段，不要带着缺失的前置知识继续。

## 三个月后的成果

- 能解释 URL、HTTP、DOM、CSS、JavaScript 事件循环和浏览器渲染的关系；
- 能使用 TypeScript 建模状态、边界和失败，而不是用 `any` 隐藏问题；
- 能判断 React 状态归属、Effect 是否必要以及 Query Cache 如何保持一致；
- 能实现可分享 URL、可访问表单、认证流程和失败恢复；
- 能对照 D1/R2 与 .NET API，理解前端所依赖的 Contract；
- 能选择单元、组件、集成和 E2E 测试，并从 CI 日志定位问题；
- 能独立交付一个跨前端、API、持久化和测试的功能切片。
